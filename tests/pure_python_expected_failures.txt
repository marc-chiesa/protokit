# Pure-Python protobuf known-failure inventory (0.16.0 U2, KTD10).
#
# Applied by tests/_pure_python_inventory.py only when the suite runs under
# PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python: each listed test gets a strict
# xfail naming the exception below, so the test-pure-python CI cell is red only
# on a new failure, an XPASS (a fix landed: delete the entry), a failure whose
# exception changed, or a stale entry. Not read under upb.
#
# Format (see the module docstring): a `protobuf:` / `python:` header recording
# the runtime the entries were measured on, then one entry per line:
#   <node id> <finding[,pin-id...]> <exception[,exception...]>
# Entries are harvested from the cell's own run (its harvest step prints them),
# never from a local measurement.
#
# First harvested from the cell's first run on PR #59:
#   https://github.com/marc-chiesa/protokit/actions/runs/34425343201/job/102709277970
# (173 entries: 166 V34, 5 V10, 2 V1). Every entry flipped when U3 closed those
# findings and was deleted; the inventory is EMPTY and the cell is a required
# check (U23). An empty inventory carries no header. A new entry needs the
# `protobuf:` / `python:` header above it, copied from the cell's harvest
# output. Note what an entry does: it makes the required check TOLERATE that
# one failure (strict xfail), so adding one is a reviewable decision to ship
# with a known pure-Python defect, and the release gate requires this file
# to be empty again before a release is cut.
